# 桌面性能分析记录

日期：2026-10-26。适用源码：桌面 0.4.0-beta.39，.NET 10 / Avalonia 12.1.1。

## 分析范围

检查播放与缓冲、界面定时刷新、歌词塑形和逐字高亮、风格动画、歌单筛选和索引、封面缓存、文件扫描、统计保存及插件会话路径。优化保留现有功能、刷新频率、动画、后台状态同步、统计精度和增量音频解码。

## 调整

| 路径 | 原有开销 | 调整 |
| --- | --- | --- |
| 歌单筛选 | 资料库不变时仍重建订阅集合与 ID 索引；直接歌单查询也收集全库引用 | 复用有效索引，检测同数量替换与原位 ID 变化；按来源分支计算所需集合 |
| 文本搜索 | 为每首候选歌曲创建四项数组 | 直接比较字段，保留当前文化的忽略大小写规则 |
| 歌词帧刷新 | 每帧遍历虚拟列表的整个视觉子树，并计算非活动行的逐字进度 | 随视觉挂载维护当前呈现器集合，仅活动行计算时序 |
| 歌词高亮 | 重扫已唱文本元素，重复生成未变化的裁剪区与画刷 | 二分定位文本元素，缓存相同进度几何，复用画刷；文本/字体/宽度变化使缓存失效 |
| 风格动画 | 每帧新建动画字典快照数组 | 复用池化快照，保持回调可修改集合的语义；归还时清除对象引用 |
| SQLite 进度保存 | 删除检查遍历歌曲、歌单、状态与统计的全部指纹 | 将指纹分为资料库与播放状态两个分区，每个实体仅缓存一份；事务提交成功后才更新指纹 |

增量保存指纹同时包含已有的 `LyricsDisabled` 状态，避免只有取消歌词关联变化时被误判为未修改。

## 固定负载对比

运行入口：

```powershell
$env:NUGET_PACKAGES = "$PWD/.packages"
dotnet run --project tests/NonetMusicPlayer.PluginUiChecks.Desktop -c Release -- artifacts/performance --optimization
```

同一 Windows 环境，Release，Avalonia Headless；预热后使用 `Stopwatch` 和 `GC.GetAllocatedBytesForCurrentThread`。结果为循环总耗时与调用线程累计分配量，不能等同于进程驻留内存降幅。并发测试、JIT、文件系统和硬件会影响耗时。

| 固定负载 | 优化前耗时 | 优化后耗时 | 优化前分配 | 优化后分配 |
| --- | ---: | ---: | ---: | ---: |
| 2 万首歌的完整歌单，重复筛选 20 次 | 113.47 ms | 63.84 ms | 90,717,704 B | 42,498,200 B |
| 相同文本与进度，读取裁剪区 600 次 | 24.04 ms | 0.09 ms | 1,456,688 B | 80 B |
| 已呈现歌词行在固定播放位置刷新 600 次 | 14.16 ms | 1.54 ms | 3,523,280 B | 80 B |

后两个负载用于检查稳定帧的重复工作，实际逐字推进时仍需要更新裁剪区，不能据此推算所有歌词动画的提速比例。SQLite 的二十次同步保存仍主要受事务与磁盘影响，测得耗时不足以证明稳定提速；改动的确定收益是进度事务不再检查无关的歌曲指纹。

## 验证与边界

- 覆盖歌单顺序、过滤、缺失来源、同数量对象替换、原位 ID 修改、Unicode 部分字形及增量保存。
- 使用既有回归检查歌词入场前定位、换行、焦点/转场恢复、快速导航、设置草稿与滚动位置、风格覆盖/撤销、连续变形及插件重新配置。
- 音频检查覆盖有界 PCM、后台生产、缓冲饥饿、EOF、跳转与取消。
- 音频缓冲已经按需解码，封面缓存已有 LRU 与容量上限，标签扫描已有并发限制；这些路径保留现有策略。
- 不引入新的进程边界、持久化格式或插件 Contract。跨平台源码可构建性与目标平台实机表现应分别验证。
