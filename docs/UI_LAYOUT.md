# 手写桌面布局配置（版本 2）

可以用 JSON 配置工作区位置、播放器的嵌套网格、各控件的位置、跨度、大小、边距和对齐。入口集中在 **设置 → 布局配置**；客户端保留真实控件及原有命令，不执行配置里的 XAML、脚本、程序集或自定义绑定。

## 使用方法

1. 在设置中打开配置文件，使用自己的编辑器修改；设置不展示 JSON 内容。也可导入 `samples/layouts/default.layout.json` / `compact.layout.json`。
2. 保存修改后先校验文件，再重新加载。可以导出一份已应用配置作为个人模板；导入也会校验实际尺寸后应用。
3. 活动文件位于数据目录下的 `Layouts/active.layout.json`。不会自动监视文件，避免未写完的文件被即时应用。
4. 恢复默认会应用内置布局；恢复备份会使用 `active.layout.json.bak`。首次有效修改后才有备份。

默认数据目录为可执行程序所在目录的 `Data`；设置可选择其他目录，或使用 `NONET_DATA_DIR` 隔离测试。活动布局在 `Layouts/active.layout.json`；恢复文件在可自定义的备份目录，默认 `Data/Backups`，旧相邻备份只读兼容。发布脚本保留便携数据并留存旧包，不覆盖个人布局。

应用前先完成完整语法和 Contract 校验。验证失败时不写入活动配置，保留当前可用布局并报告类似 `$.player.items[1].grid.items[0].width` 的具体位置；JSON 语法错误报告行号和字节位置。语法校验不等于在任意窗口尺寸下都有足够显示空间，应在当前窗口和最小窗口检查效果。必要控件不能删除、重复或隐藏；客户端排版层负责检测不足的显示空间并保护操作入口。

启动时文件损坏会保留原文件，优先使用有效 `.bak`，否则使用默认布局；应用有效配置不会用损坏的原文件覆盖上次有效备份。保存通过临时文件和原子替换完成。正常保存会备份上一份实际可用配置，外部编辑为语法正确但排版不可用的文件不会取代它；恢复备份成功后，原活动布局成为下一次可恢复的备份。

客户端还会检查实际像素格位，拒绝越界、裁切或覆盖相邻控件的布局。窗口缩小或拖动降低播放栏高度时，无法容纳的布局临时回退默认；原文件不修改，空间恢复后会重新尝试。外部编辑器的未保存修改由编辑器管理；播放器仅重新加载磁盘上已经保存的文件。

导航宽度通过区域边界拖动调整；播放栏高度只能通过进度条下方、三个播放按钮上方的中央短手柄调整，避免与进度调节冲突。支持鼠标与触摸，松开后保存。自定义 `workspace` 坐标会回到相邻区域排布，同时保留嵌套播放器配置及备份。默认高度为 96 px，触摸输入自动使用至少 110 px，极窄窗口自动使用 128 px，复杂布局需拖高播放栏。

进度条固定覆盖播放栏顶部边界，圆形滑块完整保留在左右边缘内；JSON 中的 progress 身份仍必须保留，行列位置不改变其顶部叠层。中央短手柄不覆盖进度条。桌面歌词按钮会和音量工具对齐；界面字体可选择系统字体或导入字体文件，外部编辑器的字体不受影响。

## 顶层字段

新配置的 `schemaVersion` 必须为数字 `2`。`player` 是必须的网格对象；`workspace` 可以省略或为 `{}`，表示使用软件的默认工作区排布。版本 1 的旧配置仍能读取，并自动升级，规则见下方“旧配置迁移”。

需要自由安排工作区时，`workspace` 必须同时包含下面三个区域，且不能相互重叠：

```json
"workspace": {
  "Navigation": { "x": 0, "y": 0, "width": 0.18, "height": 0.84 },
  "Content": { "x": 0.18, "y": 0, "width": 0.82, "height": 0.84 },
  "Player": { "x": 0, "y": 0.84, "width": 1, "height": 0.16 }
}
```

坐标相对于标题栏下方整个工作区，左上角为 `(0,0)`，右下角为 `(1,1)`。区域宽度至少 `0.12`，高度至少 `0.1`；区域不能超出工作区。比例只是声明，仍须给导航、曲库和播放栏留足实际空间。修改三块区域不会移除它们的搜索、导航、设置和音乐功能。

## 网格与控件

每个网格包含 `rows`、`columns`、`items`。行和列都使用字符串数组：

- `"Auto"`：按内容需求分配。
- `"*"`：分配一份剩余空间；`"2*"` 分配两份。星号系数为大于 0、不超过 100 的数字。
- `"44"`：44 个设备无关像素。固定值大于 0、不超过 2000。

固定数字采用小数点，不使用单位或逗号，例如 `"44.5"`。推荐用星号列承载较长标题、用固定列保证按钮不会挤压；像素/星号数合法并不保证空间足够。每个网格有 1～24 行和 1～24 列，最多嵌套 4 层，总计最多 128 项。

`items` 中每项必须二选一：`id` 指定一个现成控件，或 `grid` 包含子网格。它们都可以设置以下布局属性：

| 字段 | 规则 |
| --- | --- |
| `row`, `column` | 必填，从 0 开始的整数索引 |
| `rowSpan`, `columnSpan` | 默认为 1，至少为 1，不能超出所在网格 |
| `margin` | 默认为 `[0,0,0,0]`，依次为左、上、右、下，各值 0～64 |
| `horizontalAlignment` | `Stretch`（默认）、`Left`、`Center`、`Right` |
| `verticalAlignment` | `Center`（默认）、`Stretch`、`Top`、`Bottom` |
| `fontSize` | 可选，10～32；作用于支持文字字号的控件 |
| `width`, `height` | 可选，8～512；操作按钮至少 32；未设置时保留控件的默认尺寸/适应尺寸 |

同一个网格里的项不能占用相同单元格，即使控件设置为左/右对齐也不允许重叠。父级容器可以跨行列，子级网格内部另外安排自己的控件。

整个控件树必须恰好包含一次以下 12 个 ID，大小写敏感。独立的 `lyrics` 按钮已经移除，封面仍然负责打开歌词：

| ID | 真实功能 |
| --- | --- |
| `artwork` | 当前歌曲封面、打开歌词 |
| `title` | 当前歌曲标题 |
| `artist` | 艺术家信息 |
| `previous` / `play` / `next` | 上一首、播放/暂停、下一首 |
| `time` | 当前进度与总时长 |
| `mode` | 列表循环、单曲循环、随机播放的切换 |
| `favorite` | 添加/移除“我喜欢”；激活时红色爱心 |
| `more` | 歌曲附加操作菜单 |
| `volume` | 音量调节 |
| `progress` | 显示进度并跳转播放位置 |

进度条固定在整个播放栏最上沿，左右延伸到边缘。为兼容已有版本 2 文件，配置中仍须保留 `progress` ID；它的格位、边距和对齐不再改变实际进度条的位置。桌面歌词开关也固定在播放栏右侧，确保任何布局下均可访问。`compact.layout.json` 提供较小封面和按钮的例子；其原有底部进度条格位只作兼容保留。

默认布局的中央三个 `70` 像素格位内是 `50×50` 的透明播放按钮。左侧 `60×60` 封面占 `80` 像素列，标题 18、艺术家 16；右侧为时间、播放方式、喜欢、更多和音量。窄窗口默认布局使用 `44×44` 播放操作，并把时间放到功能按钮下方；播放器依旧居中，必要操作不会隐藏。自定义布局若空间不足则临时回退默认布局，配置文件保留。圆角、图标绘制、红心状态和交互由客户端提供。

## 旧配置迁移

版本 1 布局不需要手动重写。读取时客户端先校验原有字段、ID、尺寸、跨度和占格，再移除 `lyrics` 这一项；如果它位于单独子网格且移除后为空，只移除那个空容器，父网格的行列和空格位仍保留。其他 12 个必要控件必须齐全且各出现一次。已经手动移除 `lyrics` 的版本 1 配置也能升级。

旧配置的显式尺寸和字号不会改动。原来省略的按钮尺寸会写成旧版实际值：上一首 / 下一首 / 功能按钮 36，播放按钮 42，封面 60，进度高度 32；省略的歌曲标题 / 艺术家 / 时间字号分别为 16 / 12 / 11。这样不会因为新版默认按钮变大而把旧的 44 或 38 像素列挤坏。工作区比例、行列、边距和跨度不随迁移变化。

启动或应用版本 1 配置时，原始文本首先另存为 `active.layout.json.schema1.bak`，随后活动文件保存为版本 2；已有 `.schema1.bak` 不会被重复升级覆盖，已有有效 `.bak` 不会被启动迁移覆盖。`.schema1.bak` 是原始迁移留档，普通 `.bak` 是上次实际可用布局，两者用途不同。恢复原始布局时可把 `.schema1.bak` 复制为一个 `*.layout.json` 文件再从设置导入，它会再次转换为兼容的版本 2；无需覆盖原始留档。

迁移不改变播放模式、音乐数据、插件和其他设置。若迁移备份或保存失败，客户端继续使用已经兼容的内存布局并报告原因，原活动文件不覆盖。语法错误或非法旧布局仍会按正常备份回退处理，不会为了迁移放宽安全检查。版本 2 不接受 `lyrics` ID，不要只把旧文件的版本号改成 2；直接保留版本 1 让客户端升级即可。

## 安全与兼容边界

- 支持 `//` / `/* ... */` 注释以及尾逗号，方便手写；文件必须不超过 100 KB（UTF-8 字节）。严格 JSON 工具可能不接受注释。
- 拒绝未知字段、重复字段、不支持的版本、负边距、无效数字、未知控件及重复/缺失控件。错误不会悄悄吞掉。
- 不接受 `visible`、`opacity`、任意 `binding`、`command`、`xaml` 或代码。功能绑定由客户端维护，布局不会改变播放、收藏或插件权限。
- 配置只描述工作区和播放器控件树，不替换曲库页面内部的数据模板，也不允许插件在布局文件中加载可执行 UI。
- 推荐把播放按钮设为 42～50 像素、其他操作按钮设为 32～40 像素、进度行至少 20～24 像素、封面设为 48～60 像素。大字号和较大边距需要更宽窗口。
- 手写布局与插件是两种不同机制。布局文件无需安装插件；音源插件继续按照独立插件 Contract 通信。
