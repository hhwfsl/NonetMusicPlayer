# 局域网设备互听

## 使用

1. 两端接入同一可信局域网，并导入本地歌曲到歌单。
2. 在接收邀请的一端打开“设备互听”，开启“共享本机音乐”。发起连接的一端会自动开启本机共享以建立双向访问。
3. 复制连接邀请，粘贴到另一端的设备互听页并连接。邀请五分钟内有效，过期后刷新。
4. 接收端接受一次请求后，双方都能访问对方共享的歌单，支持桌面↔手机、桌面↔桌面和手机↔手机。默认等待 30 秒，双方设置均可调整本机接入请求的期限（10–120 秒）。拒绝或超时不建立会话。
5. 后台收到请求时发系统通知，不要求软件一直处于焦点。Android 可直接在通知上接受/拒绝；桌面点击通知或返回 Nonet 后确认。未允许系统通知时，需要在期限内打开应用确认。厂商强制停止进程或网络不可达不属于焦点问题，仍可能无法接入。
6. 对方歌单显示在侧边栏本地歌单下方，标注“桌面”或“移动”和设备名称；在当前设备独立播放，不改变对方播放器。收藏或加入本地歌单可保留引用，来源按提供设备显示。这不是下载，离线不能播放。
7. 主动断开与正常退出发送结束通知。正常心跳间隔五秒，单次检测最长四秒；失败后按 2、4、8、15 秒退避，之后最多每 15 秒重试。连续失败只标记“暂不可用，正在重连”，保留配对、歌单和引用，不因静默时长撤销授权。网络恢复后继续原会话；受影响的播放保留进度并续播，手动暂停或切歌可取消自动继续。明确撤销凭据立即生效。

共享只包含本机已导入歌单中的本地音频、音乐标签、封面、歌词，不转发云端或其他设备歌曲，不同步设置、最近播放、统计或播放器操作。明确断开、关闭共享或正常退出后移除临时曲库，已保存歌曲仍保留；暂时断网不移除曲库。网络中断与异常关机无法仅靠心跳可靠区分，因此收不到结束通知时保持重连状态，可手动断开。

Android 休眠可能暂停网络，前台服务和唤醒锁不构成绕过系统限制的保证。恢复网络、唤醒或退出休眠时主动重试，不要求 Activity 获得焦点。需要时由用户在系统电池设置中允许后台活动，不自动修改系统白名单。进程被强制停止、共享端重启、IP/端口改变或更换证书后需要重新配对；认证不落盘，不为自动恢复放宽来源或证书校验。

远端音频增量读取并由本机解码，不是先把整首歌转换完成。首播约 250 ms PCM 预缓冲后启动，封面和歌词异步补全；正常还会有解析播放地址、TLS/HTTP 首包及服务器响应耗时，不能保证与本地文件相同。快速切歌只保留最后一个请求；不支持取消帧的旧进程插件会有界排空旧回复，不能强行中断其内部工作。

Windows 首次共享可能需要允许专用网络的防火墙访问。无须关闭防火墙，不要将端口映射到公网。访客 Wi-Fi、无线隔离、VPN 或系统后台限制可能阻止连接。Android 共享期间显示前台通知，可在通知中停止。

## 协议 v1

采用双端一致的只读 HTTPS API，邀请包含私网数字 IP、端口、证书 SHA-256 指纹和短期随机密钥。客户端固定证书并禁用重定向，不向其他地址转交认证。

- `POST /v1/pair`：限长 JSON，提交 key/deviceId/name 和可选 duplex=true。有效邀请仍需接收端用户接受，默认等待 30 秒，可设置 10–120 秒。接受后返回 deviceId/name/token/protocol 和可选 duplex 标志；拒绝/过期不授权。同一服务只处理一个待审批请求。人工等待与媒体请求分开，配对传输上限 135 秒，不改变用户设定的审批截止时间。
- `POST /v1/duplex`：批准后使用已获得的 Bearer 传递 port/fingerprint/token，供接收端反向读取。主机只取实际配对 TCP 来源，不能在 JSON 中指定任意 URL；固定回连证书指纹，授权仅可使用一次。批准之前不交付反向访问凭据。新版界面要求对端支持双向；旧 v1 客户端的一向读取接口仍保留。
- `POST /v1/disconnect`：需要有效 Bearer，撤销该设备所有会话并通知上层解除双向连接。正常退出有界发送；收不到通知时进入不可达重连状态，不推断为已撤销。
- `GET /v1/info`：设备标识与曲库 revision，用于心跳和变更检测。
- `GET /v1/catalog?offset=N`：每页最多 200 首，首响应包含歌单，最大 20000 首与 2000 个歌单。新增可选 `deviceKind`（desktop/mobile/unknown），旧设备缺省显示通用设备来源；双方需更新才能完整使用确认和平台标记。
- `GET/HEAD /v1/audio/{id}`：增量音频流，支持单个字节 Range、后缀 Range、206/416 与寻址。
- `GET/HEAD /v1/artwork/{id}`、`/v1/lyrics/{id}`：按已授权歌曲 ID 获取资产。

所有 GET/HEAD 需要内存 Bearer 会话；已批准会话不因空闲过期，仅在明确撤销或共享服务结束后失效。服务端限制会话数、并发、请求大小及配对频率。不接受任意文件路径，也没有播放控制、上传、删除或系统命令端点。歌词最多 2 MiB、封面最多 5 MiB；音频流按固定缓冲复制，不整首解码到内存。

桌面实现位于 `Core/Network`，与 Avalonia 页面分离。插件使用 SDK `network.library.v1` 与既有命令，不直接获取配对密钥，参见 [通用接口参考](UNIVERSAL_EXTENSIONS.md)。
