# Android 更新协议

## 发行命名

- 固定仓库：`https://github.com/hhwfsl/NonetMusicPlayer`，不是可编辑的第三方 APK 地址。
- 标签：`android-v0.3.0-beta.9`；APK：`Nonet-0.3.0-beta.9.apk`。桌面使用 `v0.4.0-beta.32`，两个产品独立排序。
- Release 正文是更新说明；客户端以只读、可选择的纯文本显示，不执行 HTML 或脚本。
- Release 只附一个完整通用 APK，不制作 ZIP 或拆分安装包。资产必须完整上传并具有 GitHub API 提供的 `sha256:<64 位十六进制>` digest，客户端直接使用该摘要校验。
- 从最近 100 个公开 Release 中筛选 Android 标签及对应 APK，按数值版本比较，`beta.10` 大于 `beta.9`。忽略草稿、旧版本、缺失或不可验证资产；正式安装版本不自动更新到预发布。

## 检查与交互

每次应用进程启动后，首次打开主界面只检查一次；旋转、切页和安装权限返回不重复弹窗。手动检查位于设置 → 关于。自动检查网络失败只写日志，手动检查显示可读错误。检查不会上传歌曲、数据库、设备标识或账号凭据；GitHub 正常接收网络请求的来源 IP。

发现新版本后可下载或暂不更新。下载弹窗显示真实字节进度，关闭弹窗或点击转到后台不会停止任务；再次点击通知或设置页按钮可返回同一进度。中、日、英语沿用当前应用语言。

## 下载生命周期

用户发起后使用 Android `dataSync` 前台服务，不依赖 Activity 存活。前后台共用一个网络请求和一个临时文件。前台显示弹窗；后台通知显示进度和取消。通知权限被拒绝时说明限制并保留前台弹窗，不谎称通知可见。

取消会中止网络读取，在关闭文件句柄后删除本次临时文件；失败同样清理。状态与通知不沿用上一次下载的百分比。服务被系统超时停止或正常销毁时取消；强制杀进程可能来不及清理，下一次启动负责删除残留 `pending.part`。

最大 APK 256 MiB。HTTPS 起始地址必须来自固定仓库的 Release；重定向只允许 GitHub 的已知 HTTPS 资产域名。不携带认证头，不接受 HTTP 降级。流式读取并核对长度和完整 SHA-256，不把完整 APK 解码进内存。

## 安装安全

校验 Android 包名、递增 `versionCode`、与 Release 一致的 `versionName`、设备最低 SDK 和当前安装的签名证书。不同签名不能覆盖原安装，不以卸载旧版的方式绕过签名检查。

校验后，APK 单独放在应用缓存的安装子目录；FileProvider 仅向系统安装器授予单个 APK 的临时只读 URI，不公开音乐、数据库、下载正文或整个缓存。

首次更新可能打开“安装未知应用”设置，返回后继续请求系统安装。用户拒绝权限或取消安装时不丢弃音乐库，可在设置重试；不会静默安装。前台完成直接请求安装，后台完成使用可点击安装通知，不绕过 Android 后台 Activity 启动限制。

成功升级后下一次启动清理已过时的 APK 与更新记录。未完成安装的已验证包只保留一份，可重试或取消删除。缓存可能被系统回收，届时需重新下载。

## 签名与验证

当前预发布沿用原测试签名；维护者保管 keystore，不上传仓库。默认自行构建会产生自己的调试签名，不能覆盖不同签名的官方安装包。若改用正式签名，须先规划数据迁移与 Android 签名轮换支持，不能简单更换私钥。

回归测试使用模拟 Release/HTTP 响应及仅存放在本地 artifacts 的更高版本同签名 APK，不向 GitHub 上传假更新，也不实际安装 QA 升级包。测试覆盖版本排序、混合桌面标签过滤、摘要/长度/重定向校验、前后台切换、通知取消清理、真实 APK 身份验证及系统安装界面。
